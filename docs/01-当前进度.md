## 下一步建议

下一步技术学习建议继续异步与长任务服务化，进入原生异步工具 SDK 调用：

```text
当前已完成 async runner、状态记录、超时等待、取消、并发测试、并发限制、FastAPI 后台任务 API、真实 DefenseTask 当前步骤后台执行、原生异步 LLM SDK、工具同步阻塞隔离边界、后台任务幂等请求，以及后台任务状态持久化恢复。
下一步要让工具执行侧从线程隔离逐步过渡到原生异步调用能力。
Qdrant cron / Kubernetes CronJob 长期调度证据继续保留为运维验证线，不阻塞异步学习。
```

原因：

```text
项目已有 FastAPI、SSE、WebSocket 和 DefenseTask 长任务场景，异步阶段可以直接提升服务端并发能力。
当前 DefenseTask 可以作为后台任务执行，LLM 已使用原生异步 SDK，工具调用仍通过线程边界隔离。
幂等请求已经让 HTTP 重试、页面重复点击和网络抖动下的重复执行行为可控。
后台任务持久化恢复已经让服务进程重启后的任务状态可审计。
继续推进原生异步工具 SDK，才能减少线程池隔离对高并发场景的资源压力。
```
